# Sent vs stored

Every body below was sent through the GitHub MCP tools from a Claude Code cloud session, then read back. Inputs and outputs are in [`github-calls.md`](github-calls.md). The PR description was also read through the REST search API (`gh api search/issues`), outside the MCP server, and came back identical to the MCP read.

| Case | Write tool | URL lengths sent | Result |
| --- | --- | --- | --- |
| Case 0 | `create_pull_request` (PR description) | 149, 150 | 150: wrapped in 2 backticks; 149: unchanged |
| Case 1 | `add_comment_to_pending_review` | 103 | unchanged |
| Case 2 | `add_comment_to_pending_review` | 104 | unchanged |
| Case 3 | `add_comment_to_pending_review` | 149 | unchanged |
| Case 4 | `add_comment_to_pending_review` | 150 | wrapped in 2 backticks |
| Case 5 | `add_comment_to_pending_review` (multi-line) | 150, 151, 152 | 150: wrapped in 2 backticks, 151: in 3, 152: in 4 |
| Case 6 | `pull_request_review_write` `submit_pending` (review body) | 149, 150 | 150: wrapped in 2 backticks; 149: unchanged |
| Case 7 | `add_issue_comment` | 149, 150 | 150: wrapped in 2 backticks; 149: unchanged |

URL lengths count every character from `https://` through the `#L1-L3` anchor; only the blob links under test are listed. The 22-character `https://claude.ai/code` footer link is unchanged in every body.

Separately, the PR description's footer was replaced: the body was sent ending with `🤖 Generated with [Claude Code](https://claude.com/claude-code)` and the session link, and was stored ending with `---` and `_Generated by [Claude Code](https://claude.ai/code)_`. That looks like attribution labelling by the session, not the link bug, and is recorded here only so the diff below is complete.
